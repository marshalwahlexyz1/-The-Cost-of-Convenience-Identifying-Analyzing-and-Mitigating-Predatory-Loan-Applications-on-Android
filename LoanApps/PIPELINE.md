# LoanWatch — Automated Compliance Audit Pipeline

## Overview

The pipeline automates loan app compliance analysis across 7 stages, from LLM-based policy extraction through static and dynamic analysis. App collection and regulatory PDF collection remain manual; everything else runs via a single orchestrator script.

```
python3 pipeline.py
```

## Stage Details

### Stage 0 — Policy-to-Permission Mapping (`policy_extractor.py`)

Uses the **Groq API** (`llama-3.3-70b-versatile` by default) to read each country's regulatory PDF and extract prohibited Android permissions. Produces:

- `LoanPolicyandlist/extracted_permissions.json` — structured per-country permission sets
- `permission_sets.py` — Python config with `COUNTRY_SETS`, `GOOGLE_PERMS`, `LOANWATCH_PERMS`

**Requires a Groq API key.** Get one free at [console.groq.com](https://console.groq.com).

**Configure policy PDFs** in the `POLICY_MAP` dict at the top of `policy_extractor.py`:

```python
POLICY_MAP = {
    "Nigeria":     ["FCCPC_DML_Guidelines_2022.pdf"],
    "Kenya":       ["CBK_Digital_Credit_Providers_Regulations_2022.pdf"],
    "Pakistan":    ["SECP_Digital_Lending_Policy_2022.pdf"],
    "Philippines": ["Digital Lending in the Philippines- ...pdf"],
    "Indonesia":   ["OJK_POJK_10_2022.pdf"],
    ...
}
```

Only regulatory text PDFs should be listed here — not the app-registry/list PDFs.

### Stage 1 — Permission Analysis (`analyzeapk.py`)

Scans all APKs in country folders using **Androguard**, extracts declared permissions from each `AndroidManifest.xml`, and flags apps against:
- Country-specific prohibited sets (from `COUNTRY_SETS`)
- Google Financial Services Policy set (`GOOGLE_PERMS`)
- LoanWatch superset (`LOANWATCH_PERMS`)

### Stage 2 — Filter Violators (built into `pipeline.py`)

This was the **missing glue step**. Reads `permission_reporttest.csv`, keeps rows where `ViolateLoanWatch == TRUE`, collects the specific violating permissions, and writes `Results/violating_loanwatch.csv` — the file that all downstream stages depend on.

### Stage 3 — Copy Violating APKs (`copyviolatingapps.py`)

Reads `violating_loanwatch.csv`, matches package names to APK files across all country folders, and copies them into `SensitiveAPIAnalysis/{Country}{Status}/` for deeper analysis.

### Stage 4 — Sensitive API Analysis (`apianalysis.py`)

Analyses the staged APKs' Dalvik bytecode using Androguard to confirm which sensitive APIs are actually invoked — not just declared in the manifest.

### Stage 5 — FlowDroid Data Flow Analysis (`dataflowanalysis.sh`)

Runs **FlowDroid** on every APK in `SensitiveAPIAnalysis/`, using `sourcesandsinks.txt` to define sensitive data sources (contacts, call logs, SMS, media) and network sinks (OkHttp, Retrofit, HttpURLConnection). Produces one XML result file per app.

### Stage 6 — Parse Results (`dataflowanalysisresultparser.py`)

Reads the FlowDroid XML files and produces:
- `source_leak_summary.csv` — presence of each source API per app
- `source_counts.txt` — how many unique apps use each source
- `SensitiveAPIAnalysis/Results/appmethods/{Country}/{app}.txt` — per-app leak detail

## Usage

### Full pipeline (all stages)
```bash
export GROQ_API_KEY="gsk_..."
python3 pipeline.py
```

### Skip the policy stage (permission sets already configured)
```bash
python3 pipeline.py --from permission
```

### Resume from a specific stage after a failure
```bash
python3 pipeline.py --from flowdroid
```

### Run only one stage
```bash
python3 pipeline.py --only filter
```

### Skip one stage
```bash
python3 pipeline.py --skip flowdroid
```

### List all stages
```bash
python3 pipeline.py --list
```

### Run policy extraction standalone
```bash
export GROQ_API_KEY="gsk_..."
python3 policy_extractor.py                  # all countries
python3 policy_extractor.py --country Nigeria  # single country
python3 policy_extractor.py --list-models      # see available models
```

## Groq API Setup

1. Sign up at [console.groq.com](https://console.groq.com)
2. Generate an API key (free tier is sufficient)
3. Export it before running the pipeline:

```bash
export GROQ_API_KEY="gsk_xxxxxxxxxxxxxxxxxxxx"
```

Or add it permanently to your shell profile:
```bash
echo 'export GROQ_API_KEY="gsk_..."' >> ~/.bashrc
source ~/.bashrc
```

**Default model:** `llama-3.3-70b-versatile`
**Alternative:** `mixtral-8x7b-32768` (larger context window, use for very long policy docs)

To change the model:
```bash
python3 policy_extractor.py --model mixtral-8x7b-32768
```

## What Was Automated vs. What Remains Manual

| Task | Status |
|------|--------|
| App collection (Play Store, AndroZoo, APKCombo) | Manual |
| Regulatory PDF collection | Manual |
| Policy PDF → country mapping (`POLICY_MAP`) | Manual (one-time config) |
| Permission extraction from policy PDFs | **Automated (Groq LLM)** |
| APK permission analysis | **Automated** |
| LoanWatch violation filtering | **Automated** |
| Copying flagged APKs for deep analysis | **Automated** |
| Sensitive API bytecode analysis | **Automated** |
| FlowDroid taint analysis | **Automated** |
| FlowDroid result parsing | **Automated** |
| Frida dynamic instrumentation | Semi-automated (requires physical device) |
